## Findings

### 1. Circuit breaker can lose a trip while cutover temporarily owns the same schedule id  [id: 43ea5660  ·  confidence: 8/10]

- **Severity:** medium
- **Category:** bug
- **File:** `bin/terminal-cron:370`
- **Score impact:** correctness -10, architecture -10

**Definition**

`maybeCircuitBreak` returns without tripping if `readDisabled().has(scheduleId)` is true at `bin/terminal-cron:370`, and also returns at line 383 if the atomic add finds another writer already inserted the id. During apply mode, `applyCutover` disables the repo schedule ids before quiesce and later calls `enable(down.changed)` from the `finally` block at `bin/lib/cutover-core.mjs:117`. If the affected schedule is already running and reaches the circuit-breaker while cutover has temporarily disabled that same id, cron treats the temporary cutover pause as "already disabled" or "another writer won", emits no HITL/log, and cutover then removes the id in `finally`. The lock fixed cross-id clobbering, but the flat set still has no ownership/reason semantics.

**Reproduction**

Use one repo schedule `sched-a` with enough recent failed runs to satisfy `CIRCUIT_BREAK_AFTER`. Start cutover apply so `setRepoSchedulesDisabled(... disable: true)` adds `sched-a`, then let the already-running `sched-a` cron process fail before cutover's `finally` runs. `maybeCircuitBreak('sched-a', sched)` observes `sched-a` in `disabled.json` and returns false; cutover then re-enables `down.changed`, leaving `disabled.json` empty even though the circuit breaker should have durably disabled the schedule.

**Fix prompt**

Fix the same-schedule cutover/circuit-breaker race in `bin/lib/disabled-store.mjs`, `bin/lib/cutover-core.mjs`, and `bin/terminal-cron`. Preserve backward compatibility with existing `{ scheduleIds: string[] }` files, but add ownership/reason semantics so cutover removes only its own temporary token while terminal-cron's circuit breaker can add a durable breaker reason even if a cutover token is already present. Update `readDisabledIds` so existing readers still see the union of disabled ids, update cutover to remove only its cutover reason, update cron to emit HITL/activity when it adds the breaker reason, and add a regression test where `sched-a` is cutover-disabled, circuit-breaks, and remains disabled after cutover re-enable.
