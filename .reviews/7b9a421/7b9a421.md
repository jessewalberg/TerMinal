## Findings

### 1. HTTP 500-class failures still count as wedges  [id: 10236e29  ·  confidence: 9/10]

- **Severity:** medium
- **Category:** bug
- **File:** `src/main/wedged-session-detector.ts:37`
- **Score impact:** correctness -10, conformance -10

The acceptance criteria require transient HTTP `429/5xx` failures to be excluded. `TRANSIENT_FAILURE_RE` only matches `429|502|503|504`, so repeated `500` or `501` responses still survive `isTransientOrConfigFailure()` and can file false-positive wedged HITLs.

**Fix prompt**

Fix the wedged-session transient carve-out in `src/main/wedged-session-detector.ts` so all HTTP 5xx responses are classified as transient/config failures, not only 502-504. Add focused tests in `src/main/wedged-session-detector.test.ts` that prove repeated `500` and `501` Bash failures do not produce wedges, while the existing same-command same-error non-transient positive control still wedges. Keep the change scoped to the detector and preserve the existing `429`, network, auth, MCP, and EACCES coverage.

### 2. Codex attended sessions bypass the human-input gate  [id: 314d7f21  ·  confidence: 9/10]

- **Severity:** medium
- **Category:** bug
- **File:** `src/main/wedged-session-detector.ts:536`
- **Score impact:** correctness -10, conformance -10

F-7 says attended sessions should be skipped when a human typed after the last error. That gate is only applied in `scanClaude()` via `lastHumanInputAt()`, while `scanCodex()` pushes every wedge returned by `findWedges()` without checking Codex `event_msg/user_message` turns. Codex transcripts do record user messages, so interactive Codex sessions remain in scope and can still produce false-positive HITLs.

**Fix prompt**

Apply attended-session suppression to Codex scans in `src/main/wedged-session-detector.ts`. Add a Codex human-input timestamp helper that reads recent `event_msg` rows with `payload.type === "user_message"` and a non-empty `payload.message`/text field, then skip Codex wedge parts when that timestamp is greater than `part.lastSeenAt`, matching the Claude behavior. Add tests in `src/main/wedged-session-detector.test.ts` for an attended Codex session with a user message after repeated failures (no wedge) and an unattended Codex session with the same repeated failures (still wedges).

### 3. Fresh edit-conflict tails are deferred forever without a later tool event  [id: f9ee4bc1  ·  confidence: 8/10]

- **Severity:** medium
- **Category:** bug
- **File:** `src/main/wedged-session-detector.ts:231`
- **Score impact:** correctness -10, conformance -10

`isUnconfirmedEditConflict()` decides whether the recovery window elapsed by comparing the error timestamp to `events[events.length - 1].ts`. If a transcript ends immediately after three repeated edit-conflict errors, every later scan sees the same last tool event timestamp and keeps filtering all three errors as "unconfirmed." A genuinely unrecovered edit-conflict loop at the session tail therefore never gets re-evaluated before the file ages out of the freshness window.

**Fix prompt**

Make deferred edit-conflict rechecks advance across scans in `src/main/wedged-session-detector.ts`. Pass an explicit scan timestamp or use the transcript file mtime as the captured-through timestamp, and have `isUnconfirmedEditConflict()` defer only while that captured-through time is less than `RECOVERY_WINDOW_MS` after the error. Add tests that freeze/inject the scan time: one fresh edit-conflict burst still defers before two minutes, and the same unrecovered burst is detected after the recovery window even when no later unrelated tool event was written. Preserve the existing recovered edit-conflict tests.
