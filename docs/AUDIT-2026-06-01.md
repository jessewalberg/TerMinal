# TerMinal — Audit & Native-Swift-Port Report

> Generated 2026-06-01 by a multi-agent audit workflow (18 agents: 7 review
> dimensions with adversarial verification of every critical/high finding + a
> 4-facet native-Swift evaluation). Baseline at audit time: `bunx tsc --noEmit`
> exits 0; 193 tests pass in ~220ms. All file:line references are against

## Executive summary

- **The app is healthy.** `bunx tsc --noEmit` exits 0, 193 tests pass in ~220ms, and the worst structural risks are *latent* (maintenance drag, drift surface) — not active failures. Nothing in the audit breaks the daily-driver loop today.
- **The "no console output" bug IS a real bug — found and fixed.** The audit's automated verifier wrongly cleared it (it checked the IPC *wiring*, not the *transform*). Root cause: `sanitizeLog` collapsed every CRLF (`\r\n`) line to blank, so a finished run's log pane rendered empty except the `\n`-only banner. Fixed by normalizing `\r\n`→`\n` before carriage-return overwrite collapsing, plus widening the CSI regex to strip private-marker sequences (`\x1b[>4m`/`\x1b[<u`) that were leaking as visible `[>4m[<u`. Details + correction in §4.
- **Highest real risk is the 3-layer string-keyed IPC contract** (`index.ts` 130 handlers ↔ `preload/index.ts:14-263` 138 bridge methods ↔ hand-written `GtApi` at `types.ts:549`) with zero compile-time linkage — a channel typo or signature drift stays green under `tsc` and surfaces as a dead button or hang.
- **The other verified high-severity items are duplication, not breakage:** `bin/terminal-cron` hand-mirrors the `agents.ts` run pipeline (pricing/ledger/HITL/sweep) and is *already drifting*; the fleet snapshot re-parses multi-MB transcripts every 3s due to a single-slot cache; and `runSpec` (the spawn entry for every run) has no test seam.
- **On the Swift question: don't rewrite. Optimize Electron instead.** Resource savings are real but modest for a single-user modern Mac (~120-180 MB idle RAM, ~7-15x smaller binary, snappier cold start). They do not justify a 5.5-8.5-month rewrite of ~14K LOC of React UI.
- **The decisive factor against porting is iteration velocity, not effort.** This is an AI-/vibe-coded solo project; LLM one-shot success for SwiftUI is materially lower than for TS/React, so a port buys a *permanent ~1.5-2x tax* on every future change — the opposite of what "keep iterating fast" needs.
- **Two no-clean-equivalent Swift pillars** (the full 18-tab UI rewrite, and a CodeMirror-grade diff/merge editor) would dominate the port; everything else (PTY/terminal via SwiftTerm, launchd, git/gh shelling, Telegram, MCP, file-state) maps cleanly to mature libraries.
- **Best path: harden the Electron seam now.** Centralize IPC channel strings + add a compile-time `Gt`/`GtApi` equality guard, de-duplicate `terminal-cron`'s pricing/ledger into a shared module, fix the transcript-cache thrash, and add a test seam to `runSpec`.

## By dimension

### Architecture
- **IPC contract has no compile-time link (verified, high).** `preload/index.ts:267` computes the real `export type Gt = typeof gt`, but `Gt` is imported by *nothing*; the renderer trusts the hand-written `GtApi` mirror via `window: { gt: GtApi }` (`types.ts:877-879`). A planted channel typo in preload left `tsc` at exit 0. `GtApi` still keeps the renderer's *own* call sites consistent, so the unguarded seam is specifically between the three hand-maintained copies.
- **`index.ts` god-file (medium).** One 1310-LOC file mixes template cloning (`:48-193`), PTY lifecycle (`:237-378`), and all 130 handlers registered at module top-level (they precede `app.whenReady` at `:1273`), with ~58 sites coupled to global `cur()` (`:220-223`).
- **`agents.ts` half-extracted persistence (medium).** The read side lives in `agent-run-log.ts` but `persistMeta/appendLog` still sit in `agents.ts:531-549` — a maintainer fixing run persistence must know it lives in two files.
- **`telegram.ts` duplicate command surface (medium).** ~40 `cmd*` handlers (`telegram.ts:194-882`) re-implement the IPC domain ops; every feature gets wired twice. Recommend a shared use-case layer both surfaces call.

### Resource usage
- **Transcript re-parse thrash (verified, high).** `fleet:list` (`index.ts:541-545`) loops every open session calling `readTranscriptStats`, which full-reads + `JSON.parse`es the whole file (`data.ts:253-325`); the single-slot cache (`data.ts:358-371`) misses for all-but-one session each 3s tick (`App.tsx:169-175`). Scales with open-session count and age — not with the 1746 on-disk transcripts.
- **Agents tab re-renders per chunk (medium).** `onOutput` does `setOutputs((o) => ({...o,[runId]: ... + chunk}))` (`agents/index.tsx:602-604`) on a 1517-LOC unmemoized component; no `React.memo` anywhere in the renderer. Split the log view into a memoized child and coalesce chunks.
- **Sync `appendFileSync` on the hot path (low).** `appendLog` (`agents.ts:543-549`) blocks the main event loop per output chunk; use a per-run `createWriteStream`.
- **launchd is correctly designed (low, positive).** `launchd.ts:91-100` uses native `StartInterval`/`StartCalendarInterval`; `bin/terminal-cron` is a one-shot with no busy loop. Keep this pattern in any rewrite.

### Complexity
- **`terminal-cron` fork (verified, high).** Pricing (`cron:56-79`) hand-mirrors `ai-pricing.ts:37-140`; `costOf` (`cron:111-113`), `writeAIRun` (`cron:107-134`), `fileHitl`/`fileTicket`, and `sweepStaleRuns` (`cron:426-489`) all duplicate `src/main`. Already diverged: cron lacks the `cacheWrite` price column and the 1h HITL dedup window. (The genuinely duplicated surface is ~300-400 LOC, not the full 1024 — much of the file is cron-only.)
- **Format-helper adoption debt (medium).** 7 `reltime` + 4 byte-identical `fmtDuration` copies despite `lib/format.ts` being tested; already behaviorally inconsistent across tabs.
- **Three run shapes + manual mappers (medium).** `agentRunToUnified`/`cronRunToUnified` (`cron-runs.ts:117,138`) enumerate every field; adding a field touches 3 types + 2 mappers + 2 writers.

### Security
- *No verified critical/high items — posture is genuinely good for a single-user local app.* Secrets are encrypted at rest via `safeStorage`/Keychain (`settings.ts`), `contextIsolation` is on, the main window loads local files only, and untrusted input reaches child processes only through argv arrays or `shq` escaping.
- **`widgets:run` is the most powerful bridge primitive (low).** `index.ts:862` → `widgets.ts:72-86` runs `exec(command)` (full `/bin/sh -c`, no allow-list) from any renderer string. Low exploitability (renderer is trusted) but total blast radius. Tighten to accept a widget id resolved main-side.
- **`open:external` has no scheme validation (low).** `index.ts:943` passes the renderer URL straight to `shell.openExternal`; same in `setWindowOpenHandler` (`:454`). Add an `http/https/mailto` allow-list.
- **`shq` divergence is a real hygiene risk (medium).** Three copies, one behaving differently — the kind of inconsistency that produces a quoting bug in exactly one path (see Top-10 #7).

### Testing
- **`runSpec` has no test seam (verified, high).** The 266-line spawn entry (`agents.ts:716-982`) inlines the concurrent-run guard, worktree selection, and finalize re-entrancy (`if (settled) return`, `:821`) while directly calling `execFileSync`/`spawn` and mutating module-level `runs`/`procs`. The codebase *knows* how to carve testable policy (`planWatchdogTimers`, `RerunDeps`) — `runSpec` just never got it.
- **Wedged-detector core untested (medium).** The current branch tests only the recovery path; the signature-bucketing + sliding-window threshold (`wedged-session-detector.ts:236-265`) and `normalizeErrorText` (`:72-84`) — which decide what counts as "the same error" — have no direct test.
- **Test-isolation leak (low).** `wedged-session-detector.test.ts:6,57-62` writes fixtures into the user's *real* `~/.claude/projects`; a killed run leaves stray dirs. Make `CLAUDE_PROJECTS` injectable.
- **Non-atomic state writes (low).** `patchSettings` (`settings.ts:249`) and `cron-runs.ts:72` use bare `writeFileSync` (no temp+rename); only `files.ts:135` is atomic. The reader is well-defended; the writer can still truncate on crash. Add one `writeJsonAtomic` helper.

## The "no console output" bug

**Verdict: a REAL rendering bug in `sanitizeLog` — found via a user screenshot and fixed.** The audit's automated verifier originally marked this finding *invalid* because it confirmed the IPC path is wired (the Agents tab consumes `agent:output` live at `agents/index.tsx:602-604`; the Runs tab fetches the full durable log at `runs/index.tsx:176`). That reasoning was incomplete: it verified the *transport*, never the *transform*. A `done` run's log pane rendered **blank** anyway.

**Root cause.** Real `claude`/`codex` PTY output is **CRLF-terminated** (`\r\n` on every line). The Runs tab pipes the log through `sanitizeLog` (`runs/index.tsx:8,176` → `<pre>` at `:529`). Its `collapseCarriageReturns` split on `\n` and then, for each resulting line, kept the segment *after* the last `\r`:

```js
line.split('\r')            // "…model.\r"  ->  ["…model.", ""]
parts[parts.length - 1]     // keeps ""  ->  whole line wiped
```

So every `\r\n` line collapsed to empty. Only the run banner (emitted with `\n` alone) survived — exactly the screenshot: 3 banner lines, blank middle, then a stray `[>4m[<u`. The existing tests only covered *in-line* overwrites (`10%\r50%\r100%`), never `\r\n`, so the gap was invisible.

A second, smaller bug rode along: the CSI regex parameter class was `[0-9;?]`, which omits the private-marker bytes `<` `=` `>`, so `\x1b[>4m` / `\x1b[<u` (Kitty-keyboard / modifyOtherKeys teardown) leaked through as visible `[>4m[<u`.

**Fix (`src/main/.../lib/sanitizeLog.ts`, TDD).**
1. Normalize `\r\n`→`\n` *before* collapsing carriage returns, so a `\r` that merely precedes a newline is treated as a line ending, not an in-line overwrite. Bare-`\r` progress bars still collapse to their final state.
2. Widen the CSI matcher to the full ECMA-48 shape `\x1b\[[0-?]*[ -/]*[@-~]` so private-marker/intermediate sequences are stripped.

Four regression tests added (CRLF preservation, real CRLF body, mixed bare-`\r` overlay, private-marker CSI). Suite: 193→197 pass, `tsc` clean. Verified against the real on-disk log: 0 visible lines → 32 lines, `[>4m` gone. Shipped via `bin/release`.

**Residual (cosmetic, out of scope):** the body's first line still shows a literal `^D` — those are the *printable characters* `^` `D` (codes 94/68), claude echoing a Ctrl-D keystroke, followed by backspaces (`\b\b`) meant to erase them on a live terminal. We strip the backspaces (a `<pre>` can't apply them), so the literal text remains. Proper backspace emulation is a separate, low-value enhancement.

**Lesson for the audit pipeline:** "the channel is wired" ≠ "the output renders." A verifier that confirms data *flows* must also confirm what the data *becomes* after transforms (sanitizers, formatters) on a real fixture, not a synthetic one.

## Native Swift port — verdict

**Verdict: Don't recommend a full rewrite now. Optimize Electron instead; consider incremental native-ification only behind the existing IPC seam if web-build pain ever becomes the real bottleneck.**

**Resource delta (real but modest for this user).** Measured: `/Applications/TerMinal.app` idles at ~246 MB RSS across 4 processes with 0 PTYs; the 281 MB bundle is 232 MB Chromium frameworks + 47 MB `app.asar`. A native AppKit/SwiftUI cockpit would idle ~60-130 MB (Ghostty ~45 MB bare; a full cockpit is heavier), ship a ~15-40 MB binary, and cold-start in ~80-300ms vs Electron's ~1-4s. Net: ~120-180 MB idle RAM saved (2-4x), ~7-15x smaller on disk, snappier launch, and a *qualitative* win in input-latency/throughput under fast agent output (Metal + no GC). On a 16 GB+ Mac, idle CPU is ~0% either way and the RAM/disk costs sit in the noise. *(Memory figures are a one-shot local measurement; treat as indicative, not benchmarked.)*

**Maintainability delta (the decisive negative).** This is explicitly an AI-/vibe-coded, direct-to-main, actively-iterating solo daily-driver — its fuel is high-velocity AI codegen. LLM one-shot success for SwiftUI is measurably lower than for TS/React (Swift is underrepresented in training data), so a port imposes a *permanent ~1.5-2x tax on every future change*. The benefits a rewrite "buys" — type safety, build stability — this codebase **already has** (`tsc` clean, 193 tests in ~220ms, fast/stable `bun`+`electron-vite`; no Next.js/SSR/CSS-in-JS hairball). Swift adds Xcode toolchain + codesign/notarization friction and slower compile-test loops. *Confidence: this maintainability claim is the load-bearing one and is medium (0.78).*

**Effort estimate.** ~22-34 person-weeks (≈5.5-8.5 months solo). The 18 React tabs → SwiftUI (8-12pw, zero code reuse) and the agent runtime + run logging/streaming (4-6pw, the riskiest for silent behavioral drift) dominate; IPC/preload collapses as a transport layer but each of ~164 contracts must be re-expressed and re-tested.

**What you'd lose.** ~6+ months of zero-feature work; the AI-iteration speed that makes a solo vibe-coded tool viable; a known-stable build; and the simple "drop a folder, get a tab" extensibility. You'd also re-validate every subprocess/stream behavior (wedged-detector, run-watchdog, cursor-stream) against new PTY I/O semantics.

**Recommended path:** **Optimize Electron now** (Top-10 #1-#4, #7 — the IPC guard, the `terminal-cron` de-dup, the transcript-cache fix, the `runSpec` seam). If you ever want native craft, do **incremental native-ification behind the existing IPC** (e.g. a SwiftTerm-backed terminal pane), *not* a big-bang rewrite. Full rewrite: only justified if felt snappiness/input-latency becomes a primary goal you'll trade months for. Stay = the honest default.
